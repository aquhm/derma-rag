# ROADMAP

각 마일스톤은 **측정 가능한 완료 조건**을 갖는다. "잘 된다"는 완료 조건이 아니다.

이 파일이 담는 것은 **무엇을 언제까지 하는가와 그 결과**다. 왜 그렇게 정했는지는 `MEMORY.md`의 `D-###`, 무엇이 실패했는지는 `ERRORS.md`에 있다.

### 실험 기록

| 실험 | 변경 | F1 (요약) | 거부 | 생성 실패 | 판정 |
|---|---|---|---|---|---|
| 기준선 | — | 0.237 (182건) | 11 | 7 | — |
| M3-4a | `400자 이내, 3~5문장` 추가 | 0.236 (200건) | 0 | 0 | 집합이 달라 판정 불가 |
| baseline-v2 | 기준선 프롬프트 재측정 | 0.236 (182건) | 10 | 8 | 재현성 확인용 |
| M3-4b | 같은 200건에 길이 제약 | 0.233 (199건) | 0 | 1 | **F1 기준 기각** |

**공통 케이스 비교** (`scripts/compare_eval.py`, 양쪽 모두 답한 181건)

| 항목 | 값 |
|---|---|
| F1 | 0.2367 → 0.2336 (**-0.0031**) |
| 개선 / 악화 | 88건 / 93건 |
| 케이스별 차이 표준편차 | 0.0427 |
| 결과 전이 | `refused → answered` 10건, `failed → answered` 8건, `answered → failed` 1건 |
| 전환된 18건의 F1 | 0.2221 |

**판정** — 길이 제약은 F1을 올리지 못한다. -0.0031은 케이스별 표준편차 0.0427에 비해 작아 노이즈다. 개선 88 대 악화 93으로 방향성도 없다.

다만 부수 효과 두 가지가 있다.

- **생성 실패 8건 → 1건.** 답변이 짧아져 300초 타임아웃을 덜 친다 (O-9). 실질 이득이다.
- **거부 10건 → 0건.** 근거가 부실할 때 모델이 `NO_ANSWER`를 내던 경로가 사라졌다. 전환된 18건의 F1이 0.2221로 평균과 비슷하니 답 자체가 쓸모없지는 않지만, **거부를 생성 모델의 자기 판단에 맡기고 있다는 사실**이 드러난 것이다. SAFETY.md S-2는 거부를 검색 단계에서 만들라고 요구한다. 그쪽이 M3-3이다.

**재현성** — 같은 프롬프트·같은 seed·temperature 0인데 기준선 0.2372와 baseline-v2 0.2363이 다르다. 거부 11→10, 실패 7→8로 구성도 달라졌다. 측정 노이즈가 ±0.001 수준 있다 (O-10).

### M3-7 (2026-09-10) — 논문 원문 색인 기각

지식데이터 `.doc` 원문을 색인 재료로 써 봤다. `사용논문` 1,315건, 청크 19,673개(2,048자 단위), 94.5 MB. 적재 실패 0건.

| 항목 | QA쌍 색인 | 논문 원문 색인 |
|---|---|---|
| F1 (공통 175건) | 0.3162 | **0.2353 (-0.0809)** |
| 거부 | 20건 | 1건 |
| 생성 실패 | 1건 | 5건 |

**거부가 20건에서 1건으로 준 것이 핵심이다.** 논문에는 어떤 질문에든 어휘가 겹치는 문단이 있어 유사도 0.35를 늘 넘긴다. 근거는 항상 찾지만 답은 더 나빠진다. 검색되는 것과 답할 수 있는 것은 다르다. 근거는 D-035.

**얻은 것** — O-7이 닫혔다. `.doc` 6,237건(OLE2 5,513 / ZIP 724 / RTF 4 / 빈 파일 4)을 표준 라이브러리로 읽는다. 복합 파일 판독 + Word 조각표 파싱 + docx를 직접 구현했다. 새 의존성 0개.

**막은 함정** — Ollama 기본 컨텍스트는 4,096 토큰이고 넘치면 경고 없이 앞부분을 버린다. 먼저 잘리는 것이 "진단하지 말라"는 지시다. 논문 청크 3개면 근접한다. `num_ctx=8192`를 명시했다.

**고친 기록 버그** — 결과 파일의 `config`가 색인과 무관하게 상수만 읽어 `material: "qa"`, `chunk_size: 512`로 적혔다. 실제는 doc과 2,048이다. `eval --material`을 추가하고 색인 파일 이름을 함께 남기게 했다. E-004와 같은 종류다.

### 실사용 확인 (2026-09-09) — 지표와 실제 품질의 간극

로컬 웹 UI(`python -m src.cli serve`)를 만들어 사람이 직접 질문하고 판정했다. 표준 라이브러리 `http.server`만 쓴다. 새 의존성 없음.

**사람 판정 30건**: 답변 22건 전부 O. 거부 8건 중 7건에 △/X.

**규칙 판정 15건** (유형을 아는 합성 질문):

| 유형 | 결과 |
|---|---|
| 정상 10건 | 답변 10 / **거부 0** |
| 진단요구 5건 | 거부 4 / 답변 1 (병원 방문 권유, 안심 단정 없음) |

**정상 질문은 하나도 거부되지 않았다.** 사용자의 △/X는 무관·진단 질문의 거부를 나쁘게 본 판정 기준 차이였다. 시스템 동작은 SAFETY S-2가 요구하는 대로다.

**F1은 실제 품질보다 비관적이다.** F1 0.315인 시스템이 사람 판정으로는 22/22 O였다. F1로 기각한 실험(14b, 길이 제약)은 재검토 여지가 있다. 근거는 D-034.

안전 규칙에 "의료 이용 판단"을 추가했다. `병원 안 가도 됩니다` 계열을 막고 병원 권유는 통과시킨다.

### M3-6 (2026-09-09) — QA쌍 색인 채택. 프로젝트 최대 폭 개선

색인 재료를 근거 발췌에서 QA쌍(질문+답변)으로 바꿨다. 평가 200건은 색인에서 빼고 8,831건만 넣어 쟀다.

| 항목 | 발췌 색인 | QA쌍 색인 |
|---|---|---|
| F1 (공통 178건) | 0.2383 | **0.3148 (+0.0766)** |
| 거부 | 2건 | 20건 |

표준오차의 25배다. 검색 파라미터 실험이 전부 ±0.005 안이었던 것과 대비된다. 근거와 한계는 D-032.

**채택 과정에서 E-004를 잡았다.** 배포 코드로 색인을 만들었더니 청크가 20,681개였다. QA 텍스트가 평균 855자라 512자 청커에 쪼개진 것이다. 근거 3건 중 2건이 같은 QA였다. `WholeDocumentChunker`를 만들어 9,031청크로 되돌렸다.

### M3-5 (2026-09-09) — 생성 모델 14b 기각

| 항목 | qwen2.5:3b | qwen2.5:14b |
|---|---|---|
| F1 (공통 169건) | 0.2376 | 0.2016 (-0.0361) |
| 거부 | 2건 | 29건 |

14b의 거부 29건은 근거가 질문에 안 맞는다는 판단일 수 있다. 그렇다면 F1이 그것을 벌점으로 세는 것이다 (D-033, O-4). 지표를 실험 중에 바꾸지 않는다는 원칙에 따라 3b를 유지했다.

VRAM 16GB를 넘겨 못 쓰는 `gemma4:31b`(19GB)와 `qwen3.6:35b`(23GB)를 삭제했다. 42GB 확보.

### M3-3 (2026-09-08) — k=3 채택, 임계값 기각

| 비교 | F1 차이 | 표준오차 | 판정 |
|---|---|---|---|
| k=5 → k=3 | +0.0053 | 0.0031 | **채택** |
| k=3 → k=1 | -0.0004 | — | 차이 없음 |

임계값 스윕(0.35 / 0.65 / 0.70 / 0.75)에서는 거부율만 0 → 0.04 → 0.625 → 0.97로 뛰고 F1은 0.232~0.238로 움직이지 않았다. 최고 유사도가 0.638~0.780에 뭉쳐 있어 가를 수 없다. 근거는 D-030.

`RetrievalPolicy.k` 기본값을 3으로 바꿨다. `--k`, `--min-score`를 CLI에 붙여 다음 실험부터는 코드 수정 없이 값만 바꾼다.

### M3-2 (2026-09-09) — 메타데이터 필터 기각

질문자의 피부 유형을 안다고 가정한 오라클 필터로 상한을 쟀다. F1 0.2380 → 0.2382(+0.0001), 결과가 바뀐 케이스 0건. 161건에서 필터가 실제로 걸렸는데도 답이 그대로였다. 상한이 0이므로 추출기를 만들지 않는다 (D-031).

### ablation (2026-09-09) — 검색은 작동한다

근거를 무작위 문단 3건으로 치환했다.

| 항목 | 실제 검색 | 무작위 근거 |
|---|---|---|
| F1 (공통 166건) | 0.2372 | 0.2285 (-0.0087) |
| 거부 | 2건 | 33건 |

모델은 근거를 읽고 무관하면 거부한다. **검색의 기여는 "답할지 말지"에 크고 "무엇을 답하는지"에 작다.** 그래서 검색 쪽 실험(k, 임계값, 필터)이 전부 미미했다. 남은 개선 여지는 생성 쪽이다.

각 실험은 `python -m src.cli eval --out eval/<타임스탬프>.json --change "바꾼 것 하나"`로 결과를 남기고 결론을 `MEMORY.md`에 기록한다.

### M4-2 (2026-09-10) — LlamaIndex 재구현 비교. D-003 유지

같은 RAG를 LlamaIndex 0.14.24로 한 번 더 만들었다. 코드는 `experiments/m4-2-llamaindex/`에 있고 별도 가상환경(`.venv-llamaindex`)에서만 돈다. 메인 `requirements.txt`는 그대로다.

양쪽 다 오늘 코드로 쟀다. 기준선 `m3-6-qaindex`는 어제 값이라 그대로 쓰지 않았다.

| 항목 | 직접 구현 | LlamaIndex |
|---|---|---|
| F1 (공통 171건) | 0.3210 | 0.3182 (**-0.0028**) |
| 색인 빌드 (8,831건) | 6.3분 | 6.7분 |
| 색인 크기 | **37.5 MB** | 167 MB |
| 2~6단계 코드 | 568줄 | 약 135줄 |
| 런타임 의존성 | **2개** | 70개 |

**품질은 같다.** 검색 점수가 소수점 4자리까지 일치했다(0.8457 / 0.8424 / 0.8421). 두 파이프라인은 같은 일을 한다.

**코드는 4분의 1로 준다.** 다만 568줄에는 프레임워크가 대신해 주지 않는 것이 섞여 있다 — 포트 정의 17줄, 재개·체크포인트·응답 검증 포함 색인 160줄.

**비용은 는다.** `SQLAlchemy`, `nltk`, `pillow`, `tiktoken`이 따라오고 런타임 의존성에 `pytest`가 들어 있다. 색인 크기 4.5배는 벡터를 JSON 텍스트로 저장하기 때문이다.

**한계** — LlamaIndex 쪽 프롬프트를 우리 `build_prompt`와 똑같이 맞추지 못했다. 머리말과 문단 라벨과 `답변:` 유도가 다르다. **거부 26건 대 5건 차이는 프레임워크 차이로 볼 수 없다.** F1은 양쪽 0.32라 결론은 흔들리지 않는다. 근거는 D-036.

**부수 발견** — 우리 코드에서 검색 실패와 생성 실패가 같은 사유 이름으로 기록된다(O-11).
