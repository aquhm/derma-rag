# SAFETY

이 문서의 규칙은 협의 대상이 아니다. 어길 수 없게 만드는 것이 목표이며, 프롬프트 문구가 아니라 코드 분기와 테스트로 강제한다.

## 왜 필요한가

이 데이터는 **민감성 피부 38.44%, 염증성 피부 30.67%**를 다룬다. 이미 자극에 취약한 피부다.

사용자는 챗봇의 답을 조언으로 받아들인다. 근거 없이 생성된 제품 추천은 실제 악화로 이어질 수 있다. "학습용이니까 괜찮다"는 면제 사유가 아니다. 학습용 프로토타입도 사람이 읽고 따라 할 수 있다.

## 규칙

### S-1 · 진단하지 않는다

증상 이름을 확정하는 출력을 만들지 않는다. 이것은 의료 행위다.

**금지 패턴**

| 금지 | 허용 |
|---|---|
| "당신은 지루성 피부염입니다" | "데이터셋에는 이런 특징을 가진 사례가 다음과 같이 기술돼 있습니다" |
| "이건 여드름이 확실합니다" | "관련 문단을 찾았습니다. 정확한 진단은 피부과에서 받으십시오" |
| "○○을 바르면 낫습니다" | "데이터셋에는 ○○에 대해 다음과 같이 기술돼 있습니다" |

**단정 표현을 만들지 않는다.** "~입니다", "~하면 낫습니다" 대신 "데이터셋에 따르면", "~라고 기술돼 있습니다"를 쓴다.

`SafetyPolicy`의 금지 표현 목록에 정규식으로 등록한다.

### S-2 · 근거가 없으면 답하지 않는다

검색에서 임계값 이상의 근거를 얻지 못하면 **생성 단계를 실행하지 않는다.**

```
검색 → RetrievalPolicy.is_sufficient()
        ├ False → Refusal 반환. Generator 호출 안 함
        └ True  → 생성 진행
```

이것은 프롬프트 지시가 아니라 `if` 문이다. 프롬프트는 어길 수 있고 분기는 못 어긴다.

근거는 `MEMORY.md` D-007. 테스트는 `docs/guidelines/05-testing.md`의 필수 테스트 1번.

### S-3 · 검색된 근거 밖의 내용을 만들지 않는다

프롬프트에는 검색된 문단만 넣는다. 모델의 사전 지식을 끌어오게 하는 문구를 넣지 않는다.

시스템 프롬프트에 명시한다.

```
아래 제공된 문단에 없는 내용은 답하지 마십시오.
문단에 답이 없으면 "제공된 자료에 해당 내용이 없습니다"라고만 답하십시오.
추측하거나 일반 상식으로 보충하지 마십시오.
```

프롬프트만으로 부족하므로 S-4의 출력 검사가 뒤를 받친다.

### S-4 · 생성 결과를 검사한 뒤 내보낸다

생성이 끝나도 바로 반환하지 않는다. `SafetyPolicy.check()`를 통과해야 한다.

| 검사 | 위반 시 |
|---|---|
| 금지 표현(진단 단정) 포함 | `Refusal` |
| 근거 문단에 없는 제품명·성분명 | `Refusal` 또는 경고 표시 |
| 면책 문구 누락 | 자동 부착 |

두 번째 게이트다. 첫 게이트(S-2)는 입력을, 이 게이트는 출력을 막는다.

### S-5 · 면책과 병원 안내를 항상 붙인다

`Answer`가 반환되는 **모든 경로**에 고정 문구를 부착한다. 조건부로 붙이지 않는다.

```
이 답변은 AI Hub 「문제성 피부 메이크업 추천 데이터」를 검색한 결과이며
의학적 진단이나 처방이 아닙니다.
증상이 지속되거나 악화되면 피부과 전문의와 상담하십시오.
데이터 출처: aihub.or.kr
```

출처 표기는 안전 요건이자 **이용 조건**이다 (`docs/DATASETS.md`).

### S-6 · 원본 데이터를 밖으로 내보내지 않는다

| 금지 | 이유 |
|---|---|
| `data/` 커밋 | 이용약관 위반 (`MEMORY.md` D-006) |
| 원본 텍스트를 로그에 기록 | 유출 경로 |
| 클라우드 API로 원문 전송 | 재배포 해당 여부 불명확. 로컬만 쓴다 |
| 외부 저장소 백업 | 재배포 |
| 문서에 원문 예시 붙여넣기 | 커밋된다 |

### S-7 · 사용자 질문을 저장하지 않는다

질문 자체가 개인 건강 정보일 수 있다. 이력 저장 기능을 만들지 않는다. 로그에도 남기지 않는다.

평가(`eval`)는 데이터셋의 QA쌍만 쓰며, 실사용 질문을 수집하지 않는다.

### S-8 · 이미지 관련 기능을 만들지 않는다

이 데이터셋에는 이미지가 없다. 사진으로 피부 상태를 판별하는 기능을 붙이지 않는다.

붙이려면 별도 데이터셋이 필요하고, 그 순간 의료기기 소프트웨어 규제 영역에 가까워진다. 이 프로젝트 범위 밖이다.

## 공개 배포 시 추가되는 요건

현재는 학습용이라 적용하지 않는다. **배포 결정이 나면 전부 활성화된다.**

- [ ] 개인정보 처리 방침 게시
- [ ] "의료 조언이 아님" 고지를 첫 화면에 표시
- [ ] 데이터셋 출처 표기를 눈에 띄는 위치에
- [ ] 오답 신고 경로 제공
- [ ] 저작권자(㈜데이터쿡)와 이용 조건 확인
- [ ] 사용량 제한과 남용 방지
- [ ] S-1~S-8 전체 재검증

배포 전에 `safety-auditor` agent로 전체 감사를 돌린다.

## 위반을 발견했을 때

1. 즉시 해당 기능을 비활성화한다
2. `ERRORS.md`에 기록한다
3. 어느 게이트가 뚫렸는지 특정한다
4. 프롬프트가 아니라 코드로 막는 방법을 찾는다
5. 회귀 테스트를 추가한다

**프롬프트 문구를 고치는 것으로 끝내지 않는다.** 같은 방식으로 다시 뚫린다.
