# SRS · 요구사항 명세

`docs/PRD.md`가 "무엇을 왜"라면 이 문서는 "구체적으로 무엇을"이다. 각 요구사항은 `docs/process/TRACEABILITY.md`에서 구현과 테스트에 연결된다.

## 기능 요구사항

### FR-1 · 데이터 적재
지식데이터 파일(`.json`, `.doc`)을 읽어 `Document` 목록으로 변환한다. 피부 문제 유형과 부위 메타데이터를 함께 보존한다.

### FR-2 · 청크 분할
`Document`를 문단 단위 `Chunk`로 나눈다. 최대 길이와 오버랩은 설정값이며 실험으로 조정한다. 각 청크는 원본 문서 ID와 메타데이터를 유지한다.

### FR-3 · 임베딩
청크 텍스트를 벡터로 변환한다. 배치 처리하며 중간 결과를 저장해 중단 후 재개할 수 있어야 한다.

### FR-4 · 색인 저장과 로드
벡터와 청크 메타데이터를 디스크에 저장하고 다시 읽는다. 저장 후 프로세스를 재시작해도 검색이 동작해야 한다.

### FR-5 · 검색
질문을 벡터로 변환하고 색인에서 유사도 상위 k개 청크를 반환한다. 각 결과는 유사도 점수를 포함한다.

### FR-6 · 근거 충분성 판정
검색 결과가 임계값을 넘는지 판정한다. 미달이면 생성 단계로 진행하지 않는다.

### FR-7 · 답변 생성
검색된 근거만을 프롬프트에 포함해 답을 생성한다. 근거 밖의 내용을 만들지 않도록 지시한다.

### FR-8 · 출력 안전 검사
생성 결과에 금지 표현이 포함됐는지 검사한다. 위반 시 답변 대신 거부를 반환한다.

### FR-9 · 면책 문구 부착
모든 답변에 고정 면책 문구와 데이터 출처를 부착한다.

### FR-10 · 근거 제시
답변과 함께 사용된 근거 청크를 표시한다. 사용자가 원문 위치를 확인할 수 있어야 한다.

### FR-11 · 거부 사유 표시
답할 수 없는 경우 사유와 실제 유사도 점수, 임계값을 함께 표시한다.

### FR-12 · 평가
QA쌍으로 답변 정확도(음절 2-gram F1)와 거부율을 측정하고 리포트를 저장한다. 케이스별 결과를 `eval/raw/`에 남겨 실험 간 공통 케이스 비교가 가능해야 한다.

검색 정확도(Recall@k)는 요구사항에서 뺐다. 이 데이터셋의 주석된 근거 링크로는 측정이 성립하지 않는다 (`MEMORY.md` D-029).

### FR-13 · CLI
`ingest`, `ask`, `eval`, `serve` 네 명령을 제공한다. `serve`는 127.0.0.1에만 바인딩되는 로컬 확인용 웹 UI다 (표준 라이브러리만 사용).

## 비기능 요구사항

### NFR-1 · 오프라인 동작
인터넷 연결 없이 동작한다. 외부 API를 호출하지 않는다.

### NFR-2 · 데이터 격리
원본 데이터가 저장소 밖으로 나가지 않는다. `data/`는 버전 관리에서 제외된다.

### NFR-3 · 레이어 규칙 준수
의존 방향이 안쪽으로만 향한다. 자동 검사로 강제한다.

### NFR-4 · 재현성
같은 입력에 대해 검색 결과가 동일하다. 생성은 모델 특성상 변동이 있을 수 있으며, 평가는 반복 실행으로 확인한다.

### NFR-5 · 중단 복원
장시간 작업(임베딩)이 중단되어도 처음부터 다시 하지 않는다.

### NFR-6 · 인코딩
모든 파일 입출력이 UTF-8이다.
